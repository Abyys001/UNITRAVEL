# ADR-0029 · Google Flights through Apify as an indicative flight source

Status: accepted (owner decision relayed in session, 2 Nov 2026, with the integration brief "Apify Google Flights Integration — Reference", which states "the client accepts this risk"). Amends booklet ch. 5.2 (distribution channels: "Metasearch / scraping … excluded"), the ch. 5 recommendation "Never: scraping-based sources", ch. 21.1 principle 1 ("official, contracted interfaces only") and ch. 35.1 rule 2, **for this one source only**. Interacts with ADR-0004 (price confidentiality), ADR-0014 (live data only on deployed hosts) and ADR-0021 (cached listings).

## Context
Duffel is not yet approved and the Amadeus contract is BLOCKED (STAGE-0), so deployed hosts show no flights and every search ends in "Ask our team" (ADR-0014). The owner wants schedules on screen now. The Apify actor `lergassy/google-flights-scraper` (actor id `5wus03lsx69fdRbig`) returns Google Flights itineraries: carriers, flight numbers, local times, layovers, aircraft, emissions and a price (DOCUMENTED, actor README, checked 2 Nov 2026). It does not return baggage, fare rules, seat maps or a bookable offer, and Google's terms restrict automated access (DOCUMENTED). Billing is pay-per-event: $0.001 per row, $0.001 per run start from 4 Nov 2026, free plan $5/month (DOCUMENTED). Iranian carriers are largely absent from Google Flights (INFERRED from the brief; to be OBSERVED in the smoke test).

## Decisions
| # | Decision |
|---|---|
| A1 | **Scope of the exception.** Only this actor, called through Apify's documented API (`api.apify.com/v2`) with the client's own Apify account. No scraping by our code, no other scraped or metasearch source, no bypassing of Apify or Google limits. Any further source needs its own ADR. |
| A2 | **Provider id `apify-google-flights`**, a normal `FlightSupplierAdapter` (ch. 21.2) emitting `NormalisedOffer`, so the engine, customer projection, compliance checks, offer snapshot and request flow are reused unchanged. Capabilities: `search` and `price` (revalidation by re-search) only; no seat map, order or cancel. |
| A3 | **Truth model (rule 3) unchanged.** Brand, baggage, change/refund conditions and seat selection are always `UNKNOWN`; nothing is inferred from Google text. UNKNOWN blocks sending a quote, so staff must confirm these in the external booking panel before quoting. Each offer carries `source.provider = apify-google-flights` and a provenance label "indicative". |
| A4 | **Normalisation.** Google's local times carry no zone; `tz` comes from our airport reference data, and a row whose airport is not in reference data is dropped and logged as a notice. Rows with `priceUnavailable` or a null price are not turned into offers (the contract requires a total; a zero is never substituted) and are kept in the run log for staff. Google itineraries are `SINGLE_TICKET`; self-transfer combinations come from the existing engine (ch. 22.11) over one batch run of the legs, labelled "separate tickets". Identity for revalidation: flight numbers + first local departure + cabin. |
| A5 | **Prices (ADR-0004).** Customers never see a price, price level, booking token or Google Flights link. `bookingToken`, `googleFlightsUrl`, typical price range and price level are staff-only behind `pricing.read.internal`. |
| A6 | **Cost control.** All calls go through one service that applies, in order: cache (key = provider, slices, passengers, cabin, max stops, airline filters, currency, market; customer TTL 3 h) → single-flight Valkey lock per key → budget guard → run. Every run sends `maxResults` (15 customer, 30 staff revalidation) and `maxTotalChargeUsd`. KAYAK fallback, `resolveBookingOptions` and `resolveReturnFlights` stay off. Budget pools (customer / prewarm / staff revalidation, default 40/30/30 of $5 with a $0.75 staff reserve customers cannot use) and an hourly customer-run cap are configuration in the Developer Panel, not code. Spend is estimated per run and reconciled daily with `GET /v2/users/me/limits`; the owner also sets Apify's own monthly hard cap. When the customer pool is empty, customers get cached results with their age or the request form; never a silent failure. |
| A7 | **Freshness.** Customer results show "updated N minutes ago". Staff revalidate before quoting or invoicing (one fresh run for that slice) and see "still listed / not found" and old → new price. Cached data is never presented as availability. |
| A8 | **Credentials (rule 6).** The Apify token is a provider credential, envelope-encrypted and write-only through the Developer Panel, sent only as `Authorization: Bearer`. No environment-variable fallback, never in job payloads, logs or fixtures. 401/403 marks the credential invalid and stops calls. |
| A9 | **Environments (ADR-0014).** On deployed hosts this is a live provider, disabled by default. Locally and in CI the adapter runs against recorded fixtures under a mocked HTTP layer; CI never calls Apify. One manual smoke script exists, capped at `maxTotalChargeUsd=0.02`. |
| A10 | **Compliance (rule 5).** Results pass the same carrier, party and lane policies as any provider. While Iran lanes are disabled pending counsel, Iran-origin searches (for example IKA→IST) produce no customer results whatever Google returns; this ADR does not change that. |
| A11 | **Disclosure.** Customer screens state, in en and fa, that schedules come from public listings and that availability and price are confirmed by our team. |

## Consequences
- Deployed hosts can show real schedules before any supplier contract, at the cost of an unbookable, unpriced-to-customer, third-party-maintained source that can change or stop without notice.
- Legal risk under Google's terms is accepted by the owner (brief, 2 Nov 2026). Counsel review is still owed (counsel-owed, UNKNOWN outcome) and is added to `docs/stages/STAGE-0.md`.
- Apify becomes a processor of search parameters (routes, dates, passenger counts; no names or contact data). DPIA entry to add (INFERRED: no personal data sent).
- Customer volume is capped by budget (~125 uncached customer searches/month on the free plan, brief §7); more needs a paid Apify plan, which is configuration only.
- If a contracted supplier is enabled later, this provider can be switched off in the Developer Panel without code changes.
