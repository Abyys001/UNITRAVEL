# ADR-0043 · Agents: Agent Management, Agent Dashboard, Agent Assignment and agent identity on tracking

Status: accepted (owner brief of 19 Nov 2026, "Additional Feature: Agent Management System"). Amends ADR-0042 D7–D9: "driver" is replaced by **agent** as the operational role everywhere; driver, courier, collection agent, delivery agent and logistics representative are agent **types**. Stage record: `docs/stages/STAGE-33.md`.

## Decision

1. **Terminology.** Role `agent` (was `driver`), permissions `cargo_job.agent` (was `cargo_job.driver`) and `cargo_agent.manage` (was `cargo_driver.manage`), tables `cargo_agents` and `cargo_agent_assignments`, API `/v1/admin/cargo/agents`, `/v1/agent/*`, console Agent Management (`/cargo/agents`) and Agent Dashboard (`/agent`). Migration `0034_cargo_agents.sql` renames the 0032 tables, role and permissions in place (no data loss). Tracking events stored before the rename keep their code (the table is append-only); `DRIVER_ASSIGNED` is read as `COLLECTION_AGENT_ASSIGNED` (`LEGACY_EVENT_CODES`).
2. **Agent profile.** Unique Agent ID `AG-00001` from a database sequence; agent type; responsibilities (COLLECTION, HANDLING, DELIVERY); company, vehicle, contact, notes; profile photograph (JPG/PNG, metadata stripped, virus-scanned, served by the API on the console origin only); public name (company-approved identification shown to customers, default "Agent AG-00012"); whether jobs need the agent's acceptance; active flag (deactivation needs no open jobs, removes the role, revokes sessions of agents with no other staff role).
3. **Assignment.** Staff assign one or several agents to a kind of job (COLLECTION, HANDLING, DELIVERY) in one action; only agents with that responsibility can be chosen; the same agent holds an open job of a kind once (partial unique index). Each assignment records agent, shipment (tracking number through the request), assigned time, responsibility (kind), status (OFFERED, ASSIGNED, COMPLETED, FAILED, DECLINED, CANCELLED), accepted/declined time and reason, completion time. When one delivery agent delivers, the other open delivery assignments are cancelled.
4. **Acceptance.** Agents set to require acceptance get jobs as OFFERED: they see the work and the towns but not the contacts until they accept; they accept or decline with a reason; the staff member who assigned the job is notified of a decline (`cargo.job_declined`). The customer-visible "agent assigned" event and notice happen on acceptance.
5. **Agent Dashboard.** Mobile-first; offered and open jobs, work history, job page with collection and delivery information, accept/decline, status updates through the same state machine and stage gate (ADR-0042 D8), collection and delivery confirmation with signature and photographs, handling updates (location, arrived at sorting facility, finished), failed attempts, problem reports (category, text, photos → internal note + `cargo.agent_problem` notice to staff), notes.
6. **Identity on tracking (D4 of the brief).** `tracking_events.agent_id` records the agent behind every agent update (and the audit row carries the Agent ID). The public tracking page and the customer timeline show agent-specific wording ("Assigned to collection agent", "Collection agent assigned", "Cargo collected by agent", "Cargo handled by agent", "Assigned to delivery agent", "Out for delivery", "Delivered by agent") and the agent's **public name only**: never the account name, email, phone or vehicle.
7. **Activity and performance.** The agent profile lists assigned jobs, activity (the agent's audit entries) and performance: jobs, completed, failed, declined, open, failed attempts, completion rate, on-time rate (completed within 2 h of the planned time), average time to complete, tracking updates.
8. **Customer milestone.** `DRIVER_ASSIGNED` becomes `AGENT_ASSIGNED` ("Collection agent assigned"); assignment notices use keys `AGENT_ASSIGNED:COLLECTION|DELIVERY`.

## Consequences

- Existing driver accounts (none on staging) become agents with an Agent ID and type DRIVER.
- Clear Valkey `perm:*` after deploy (renamed permissions).
