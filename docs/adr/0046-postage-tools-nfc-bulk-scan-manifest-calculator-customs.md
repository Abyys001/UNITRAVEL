# ADR-0046 · Postage tools: NFC, bulk scan, run sheet, postage calculator, customs forms

Status: accepted (owner brief of 19 Nov 2026: "add nfc scanner if possible with the browser and all the tools for postage in the system"; owner chose bulk scan, driver manifest, postage calculator and customs forms). Builds on ADR-0042/0043/0045. Stage record: `docs/stages/STAGE-33.md`.

## Decision

1. **NFC (Web NFC, Chrome on Android only).** Where `NDEFReader` exists, the scanners also read NFC tags: a tag holding the signed tracking URL (or the bare tracking number) opens the job like a scanned label. Staff can **write** a tag from the shipment page (Labels panel): one URL record, the same signed tracking URL as the label QR, so an iPhone (which reads NDEF URL tags natively) opens the public tracking page and its "Agent? Update this parcel" link (ADR-0045 D4). Browsers without Web NFC (iPhone Safari, desktop) do not show NFC buttons. No new dependency.
2. **Bulk scan.** One screen to scan many parcels in a row (camera, NFC or typed) and apply one update to each:
   - agents (`/agent/bulk`): `start_collection`, `at_sorting_facility`, `handled`, `out_for_delivery` with one location;
   - staff (`/cargo/scan`): `depart`, `arrive_customs`, `clear_customs`, `out_for_delivery` with one location and time.
   Each parcel goes through the existing single-parcel endpoint, so the state machine, stage gate, permissions, optimistic locking and audit apply per parcel; failures are listed with the server's reason and never block the others. Updates that need evidence (collected, delivered, failed attempts, receive & re-weigh) stay single-parcel. Staff look up a scan with `GET /v1/admin/cargo/scan/:trackingNumber` (ref, version, status, allowed commands).
3. **Run sheet (driver manifest).** `GET /v1/agent/manifest?date=` lists the agent's open jobs for the day (scheduled that day, or unscheduled and open), ordered by scheduled time, with addresses, contacts (accepted jobs only, as ADR-0043 D4), pieces, weight and handling instructions; `…/manifest.pdf` prints it with signature boxes. Staff print any agent's sheet from the agent profile (`GET /v1/admin/cargo/agents/:id/manifest.pdf?date=`, `cargo_agent.manage` or `cargo_request.read.any`). **Directions** (owner request 19 Nov 2026): on the job page and each run-sheet stop a Directions button offers driving directions from the agent's position in the phone's maps app (Apple Maps on iOS, a `geo:` link on Android), Google Maps, Waze or OpenStreetMap; "Route all stops" opens the day in run-sheet order as one Google Maps route (the only app that takes several stops in a link; legs of 10). These are outbound links the agent taps, shown only for accepted jobs with a real address; no map provider's scripts, tiles or fonts are loaded into our pages, so the CLAUDE.md "no Google services on user-facing paths" rule holds.
4. **Postage calculator.** Booklet 14.6: freight = rate × chargeable weight, plus surcharges. Rates are **data set by authorised staff**, never invented: table `cargo_rate_cards` per lane and service (currency, rate per kg, minimum charge, fuel surcharge %, handling fee, optional insurance %, notes), edited with `pricing.write`, every change audited. The calculator (`/cargo/calculator`, `POST /v1/admin/cargo/calculate`, `cargo_request.read.any` or `pricing.read.internal`) takes the lane, service and pieces (L×W×H, kg) and declared value, uses `cargoWeights` (ch. 14.3, the lane's volumetric divisor) and returns actual, volumetric and chargeable weight and an itemised **estimate**. Without a rate card for the lane/service it shows weights only and says the rate is not set. Iran lanes stay disabled; the calculator offers only enabled lanes. It never creates a quote; quotes keep their own flow.
5. **Customs forms.** `GET /v1/admin/cargo/requests/:ref/customs.pdf` builds a CN22 when the total declared value is ≤ £270 (or the equivalent declared in GBP only; other currencies get CN23) and every piece fits, otherwise a CN23, from the request's declared items (description, quantity, value, HS code, origin country), category from the declared purpose, weights, sender and addressee. Missing HS codes are printed blank and flagged in the console before printing. The sender still signs; booklet 14.9 keeps commercial invoices the customer's responsibility. Audited as `cargo_request.customs_form_generated`.

## Consequences

- Migration `0037_cargo_rate_cards.sql`; no new permissions.
- NFC tags are bearer links to public tracking only (same as the label QR); they never sign anyone in.
