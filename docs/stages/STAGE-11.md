## Limits and open items
- BLOCKED: **live mode** (Stripe's written approval, counsel on money transmission, sanctions exposure, Iran-connected customers, the processor/controller roles). BLOCKED: any customer-facing statement about card payment beyond the test banner.
- BLOCKED here: a run against the real Stripe test API. No test key exists in this environment, so these were not exercised against Stripe: creating a Checkout Session (`ui_mode: "embedded_page"` is the value the installed SDK defines and type-checks), the embedded form in the browser, a real signed event, a real refund, the health check call (`balance.retrieve`).
- INFERRED, to verify with real test keys: the Stripe.js initialiser for `embedded_page` sessions (the web code calls `initEmbeddedCheckoutPage` if the loaded Stripe.js has it, else `initEmbeddedCheckout`); the CSP origin list on the pay page (from Stripe's CSP guide for Embedded Checkout; `checkout.stripe.com` and `*.stripe.com` images are included because that guide lists them); the webhook event set (`checkout.session.completed|async_payment_succeeded|async_payment_failed|expired`, `charge.refunded`, `charge.dispute.*`) is what the brief names, so the Stripe endpoint must be registered for exactly these.
- Checkout sessions need at least 30 minutes to live: an invoice with less time left is not payable online (reason `EXPIRES_TOO_SOON`); under PAY_ON_TICKETING a same-day invoice near midnight Europe/London therefore has no online option. Owner decision whether that is acceptable.
- INFERRED: a payer screening hit after the money moved opens a case but still records the payment (P9); counsel to confirm.
- A staff "resend payment link" re-sends the invoice message (`invoice.issued` templates); no dedicated template, no payment receipt email and no refund-completed message (UNKNOWN: Stripe receipt emails are a Stripe account setting). Customers see PAID on the billing page.
- The eligibility seed (ALLOW for both products and GBP) is `seeded_pending_counsel`; with the flag off nothing is offered. Currency other than GBP is never offered until a policy allows it.
- The refund four-eyes threshold is the existing `WORKFLOW.paymentFourEyesThresholdMinor` (1 000.00 by default), so refunds of the typical cargo invoice are single-approver. Cash and bank-transfer refunds are outside the system.
- The mode-change approval path cannot be exercised end to end today (every change except `live` is a no-op and live is refused); it is built so the later ADR changes one constant. The refusal, the audit rows and the permission split are tested.
- Console: the earlier panels are English only by existing convention; the new payment blocks and the payments page use the console's `t()` with en and fa. Console reference screenshots now go to `test-results/shots` unless `UPDATE_SCREENS=1` (helper changed by another session); the two web pay screenshots were written to `docs/screens/web/`.
- Operational: after deploy, clear Valkey `perm:*` keys (new grants). Register the webhook URL (shown in the Developer Panel) in the Stripe Dashboard in test mode, enter the three test values, switch the provider to STRIPE, then an owner switches `payments.online.enabled` on.
