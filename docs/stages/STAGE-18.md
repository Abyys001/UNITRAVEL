Source: owner plan `misty-toasting-harp.md` (J4, J5, J6, J7-api). ADRs 0018 (activity telemetry), 0019 (Bonline telephony), 0020 (admin-assigned services), 0021 (curated and cached listings). Backend only: web, console and mobile consumption is separate work.

## What changed (DOCUMENTED)
- **Migrations 0015 to 0017** (hand-written SQL plus journal): `customer_activity` (+ `users.last_active_at`, index), `support_tickets`, `support_messages`, `call_logs` (partial unique index on source and provider reference), `curated_listings` (CHECK that a price exists only with `price_quoted`). - **Permissions** (`packages/contracts/src/permissions.ts`): `customer.read`, `service.assign` (privileged), `support.read`, `support.reply`, `call.log`, `listings.write`; admin and owner hold them by default. New error code `NOT_CONFIGURED` (501).
- **J4 activity**: `POST /v1/me/activity` (204), `GET /v1/admin/customers`, `GET /v1/admin/customers/:id/activity`; sessions write `users.last_active_at` on touch; sign-out audits `user.signed_out`; daily job `activity.prune` (90 days). Contracts in `activity.ts`.
- **J5 support and calls**: `POST /v1/support/tickets` (public, PoW after a burst, layered limits, Idempotency-Key, optional auth), `GET /v1/support/tickets`, `GET /v1/support/tickets/:ref`, `POST /v1/support/tickets/:ref/messages`; staff `GET /v1/admin/support/tickets`, `GET /v1/admin/support/tickets/:ref`, `POST .../replies` (`internal` flag for notes; external reply emails the contact through the outbox and `events.misc`), `POST .../commands` (assign, resolve, reopen, close); `GET` and `POST /v1/admin/calls`, `POST /v1/admin/calls/click-to-call` (501 NOT_CONFIGURED), signed `POST /v1/webhooks/bonline`. State machine in `packages/domain/src/support-ticket.ts` (OPEN, PENDING_CUSTOMER, RESOLVED, CLOSED, auto-close after 7 days). Vendor schema `telephony:bonline` (write-only). Contracts in `support.ts`.
- **J6 assigned services and payment page**: `POST /v1/admin/customers/:id/assignments` (`service.assign`, Idempotent, rate-limited; `AssignServiceBody`, `AssignmentResult`), `GET /v1/billing/purchasable` (`PurchasableItem`), `GET /v1/billing/invoices/:number/payment-page` (`PaymentPageView`); Developer Panel vendor `email:smtp` (host, port, user, pass, secure, from) read by `EmailSender` before `email:brevo` and the `SMTP_URL` fallback; settings `payment.offlineInstructions` and `listings.flightRoutes`.
- **J7 listings**: staff CRUD `/v1/admin/listings` (`listings.write`), public `GET /v1/listings/:vertical` (`buses`, `trains`, `stays`; label INDICATIVE, price only when quoted), `GET /v1/listings/flights` (cached live-adapter results only, `CACHED_OFFER` or `SANDBOX` with `fetchedAt`, no amounts, `NO_SOURCES` notice when empty); worker job `listings.warm-flights` every 6 hours.
- `packages/contracts/openapi.json` regenerated (235 paths). DPIA draft updated (data category, purposes, retention, R17 and R18, M20 and M21, open actions 10 and 11).

## Bug found by the tests (OBSERVED, fixed)
`CuratedListingPatch` was built with `.partial()` over fields that carry `.default()`; in Zod 4 that resets omitted fields on every PATCH (a status-only publish cleared the origin of a bus listing and failed). The patch now derives from a default-free shape; `listings.spec.ts` asserts a status-only patch parses to itself.

## Open, blocked or unknown
- **UNKNOWN**: Bonline's API, webhook payload and signature scheme. The adapter uses an INFERRED HMAC-SHA256 header `x-bonline-signature: sha256=<hex>` over the raw body and an INFERRED field mapping (`TelephonyEvent`). Click-to-call returns 501 NOT_CONFIGURED until real documentation exists. No Bonline endpoint was invented.
- **BLOCKED (owner credentials)**: no live flight adapter is enabled (Duffel and others), so `GET /v1/listings/flights` returns `NO_SOURCES` outside a developer machine; with the FAKE adapter locally it serves `SANDBOX` items only. Warm routes are set in the Developer Panel setting `listings.flightRoutes`.
- **UNKNOWN (counsel)**: lawful basis and notice text for activity telemetry; retention for `users.last_active_at`, tickets and call notes. DPIA sign-off is still pending.
- Assigned CIP is always held first (CIP at IKA is a REVIEW policy); the quote in the assignment body is then not stored and staff quote through the normal transition after release (ADR-0020). Four-eyes threshold for assignments was not added (no agreed figure).
- Assigned SERVICE invoices are not payable online until the `ONLINE_PAYMENT` policy covers SERVICE; the payment page shows offline instructions (setting `payment.offlineInstructions`, empty by default).
- Staff event stream gets a new aggregate type `support_ticket`; the console must ignore or render it.
- Frontends: see "Frontends" below.
